## 需要决定的功能差异

### 多分类与分类层级

WordWebCMS 当前每条修订只有一个 `CategoryId`，分类本身没有父分类字段。旧站有以下 4 篇多分类文章：

| 旧文章 ID | 文章 | 原分类 |
| --- | --- | --- |
| 9 | 虚拟主播模拟器 | 游戏、虚拟主播模拟器 |
| 15 | 虚拟主播模拟器 素材征集 | 游戏、虚拟主播模拟器 |
| 21 | 虚拟桌宠模拟器 | 游戏、虚拟桌宠模拟器 |
| 23 | 键盘快捷键 通用注解 | 游戏、虚拟桌宠模拟器 |

“虚拟主播模拟器”和“虚拟桌宠模拟器”的父分类均为“游戏”。新库已创建全部分类名称，但这 4 篇文章的分类暂时留空，没有自行选一个分类。因此首页能看到全部文章，两个游戏分类的导航入口目前没有文章。

可选：为 WordWebCMS 增加多分类及父分类，然后补迁原关系；或决定每篇保留哪个单分类，并接受平级显示。原关系在 `Migration-private/pending-category-relations.json`，旧 ID 到新 ID 的映射在 `import-map.json`。

可选：在反向代理加入这些站点专用 301 规则，或为 WordWebCMS 增加别名重定向功能；也可以明确放弃旧入口。正式替换域名前建议先决定这一项。

### 文章标题锚点

“虚拟主播模拟器 素材征集”开头有 3 个目录链接，分别指向普通玩家、游戏开发者、虚拟主播章节。正文和链接已保留，但 WordWebCMS 的 Markdown 渲染没有生成对应 heading ID，HTML 清理也不保留 `id` 属性；浏览器确认目标标题的 ID 为空，因此目前不会滚动到对应章节。

可选：增加与旧站锚点规则一致的标题 ID；或将这 3 个链接改成普通文字。未自动删除链接或改正文。

### 发布时间的显示时区

数据库保存了准确的旧站 UTC 时间，但当前页面直接格式化该时间，没有站点时区设置。最明显的是“随机头像生成站”：旧站上海时间为 `2024-11-17 01:06:03`，对应 UTC `2024-11-16 17:06:03`，新站页面显示 `2024-11-16`。

可选：增加按 `Asia/Shanghai` 显示时间的设置；或接受当前 UTC 日期。没有通过修改发布时间来掩盖显示差异。

### 主题与插件

旧站启用的是 `pacify`。WordWebCMS 使用 Liquid，不能直接执行 WordPress 的 PHP 主题。本次使用独立的 `lbnet` 主题保留图标、导航和备案链接，没有复制 pacify 的完整布局、样式或 WordPress 小工具系统。需要接近旧站外观时，可以继续修改这个 Liquid 主题，无需新增主题引擎。

旧库还留有一份 Contact Form 7“联系表单 1”（旧 ID 6），但该插件不在当前启用列表中，7 篇文章也没有引用该表单短代码。本次未创建可提交的联系表单。可决定保留现有邮件/QQ群联系方式，或增加表单功能后迁入。

All In One WP Security 的规则、封禁与审计日志属于旧 PHP 站点运行配置，未映射到新站。WordWebCMS 使用自身的登录、验证码、限流及角色机制。WP Mail SMTP 的实际 SMTP 配置已迁移，插件自身的统计、计划任务和日志未迁移。

### 历史修订与评论方式

14 条历史修订保留了标题、摘要、正文与修改时间，但 WordPress 这些修订没有各自的历史分类、标签和封面记录。导入时未把当前分类标签伪装成历史值；在新站恢复旧修订后，需要检查并重新选择分类、标签。原始修订记录保存在私有快照中。

WordWebCMS 当前只支持登录用户评论，没有游客姓名/邮箱评论模型；页面类型也不支持评论。本次没有已批准的旧评论需要处理，因此不影响已迁内容。如果仍需要游客评论，应先增加相应模型和审核流程。注册保持旧站的关闭状态。

## 启停与后续上线

在新站目录执行：

```powershell
.\Start-Preview.ps1
.\Stop-Preview.ps1
```

程序需要 .NET 10 ASP.NET Core 运行时。当前是手动启动的本机预览进程，未安装 Windows 服务或开机自启。重启电脑后需要再次启动。

管理员可使用私有文件中的新密码登录。需要修改密码时，可以使用“忘记密码”流程；SMTP 已配置，该操作会实际发送邮件，应由管理员自行发起。

正式切换时，需要决定以上差异，配置服务器的 HTTPS/反向代理或 IIS 站点绑定，并在“后台 → 设置”将公开根地址从本机预览地址改为正式域名。应用的监听地址、`AllowedHosts` 和反向代理信任地址也应按实际部署调整。当前没有修改 DNS、证书、防火墙或旧站绑定。

升级程序时保留 `App_Data`、`Migration-private`、`appsettings.Production.json` 以及独立主题。尤其 `App_Data/keys` 与 `Site:CookieName=WordWebCMS-lbnet` 必须一起保留，否则邮件密码无法解密。私有目录 ACL 仅允许当前用户、SYSTEM 和本机管理员；更换为 IIS 或服务账号运行时，需要给实际运行账号授予 `App_Data` 的读写权限。

旧站仍可能产生新内容。此迁移以本次快照为准，不会自动同步后续修改；正式切换前应再核对增量。导入工具拒绝覆盖非空库，不要对现在的新库重复执行 `import`。

回退只需停止新站预览；旧站及其数据库没有被替换。新站备份应同时包含 `wwcms_lbnet`、完整 `App_Data` 和部署配置。`Migration-private` 保存源快照、ID/URL 映射与验证记录，可以在决定补功能后据此补迁。
